# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Home-use IPAM shipped as a single Docker image. UI/UX text is in Polish. Model: tenant → site → network (CIDR, VLAN, gateway, DHCP range, DNS) → entries (IP, FQDN, MAC, type, status, tags).

## Commands

- Server tests: `cd server && npm test` (single file: `node --test test/api.test.js`; name filter: `node --test --test-name-pattern="validation" test/api.test.js`)
- Run API: `cd server && DB_PATH=../data/ipam.db PORT=8080 npm start`
- Web dev: `cd web && npm install && npm run dev` (Vite on :5173, proxies `/api` to :8080); build: `npm run build`
- Image: `docker build -t simpleipam .`

## Architecture

- `server/` — **zero npm dependencies**. Needs Node >= 24 (uses built-in `node:sqlite`). `src/server.js` is HTTP + static serving (SPA fallback to index.html); `src/app.js` holds all routes/validation/business logic behind a `createApi(db)` factory (testable without HTTP: `api(method, path, query, body)`); `src/db.js` owns the schema (created on open, no migrations framework); `src/ip.js` is IPv4/CIDR math. IPv4 only.
- `web/` — Preact + Vite SPA, hash routing (`#/n/<networkId>`, `#/audit`), plain CSS with theme variables. `api.js` is the only fetch layer. Vite output is copied into the image and served by the Node server.
- Image is multi-stage (`Dockerfile`); data lives in the `/data` volume. CI (`.github/workflows/ci.yml`) runs tests, builds the image and smoke-tests the running container, then pushes a multi-arch (amd64/arm64) image to GHCR (`ghcr.io/<lowercased repo>`; only on `main`/`v*` tags, PRs just build). The web stage uses `--platform=$BUILDPLATFORM` so arm64 builds don't emulate Vite.
- Scan (`POST /api/networks/:id/scan`) shells out to `ping`, so the container runs as root and is limited to /22 or smaller.
- Every mutating route writes an `audit` row via `log()` in `app.js`.
- IAM: `server/src/auth.js` (scrypt passwords, cookie sessions stored hashed, login throttle, role lookup); route-level checks live in `app.js` via `need(user, siteId, minRole)` / `needGlobalAdmin`. Routes require login unless registered with `{ public: true }`. Role scope is global (`tenant_id` and `site_id` NULL) / tenant / site; the most specific assignment wins (`auth.effective`). First registered user becomes global Admin; registration can be closed via the `settings` table. `handle()` takes a `ctx` (`token`, `ip` in; `newToken`/`clearToken` out) which `server.js` maps to the `sid` cookie — tests use that to simulate browsers (see `client()` in `test/api.test.js`).
- Web: `App.jsx` gates on `me` (from `/api/me`) and shows `Auth.jsx` when logged out; UI hides actions by `site.role` / `network.role` / `me.global_role`, but the server is the source of truth.
- `server/src/cli.js reset-admin` (password recovery), `backup.js` (VACUUM INTO snapshots, local files, cloud config in `settings.backup_config`, `runBackup`/`runDailyIfDue`), `s3.js` (hand-written SigV4 PutObject; verified against the AWS-documented signatures in `test/backup.test.js`) and `gcs.js` (service-account JWT + media upload) — no SDKs, `fetch` is injectable for tests, `/api/health` is the Docker healthcheck (public; every other `/api` route needs a session).
- `GET /api/networks/:id/issues` computes consistency warnings on the fly; DNS/DHCP exports are the `EXPORTS` table in `app.js`.
- API tokens (`api_tokens`, `Authorization: Bearer`) resolve to the owner's roles in `handle()`; token/password management is session-only (`sessionOnly`). `createApi(db, { ping })` lets tests inject a fake pinger; `handle.runScheduledScans()` is driven by a timer in `server.js` (`SCAN_INTERVAL_MIN`) for networks with `auto_scan=1` and feeds `entries.last_seen` / the `discovered` table.
- Schema changes to existing tables need an upgrade path in `db.js` (`migrateToTenants` rebuilds tables and writes `<db>.pre-tenants.bak`; `addColumn` handles plain additions) — deployed volumes outlive code, so never assume a fresh DB. `test/migrate.test.js` holds the pre-tenant DDL.
- Admin UI lives in `web/src/Admin.jsx` (tabs under `#/admin/<tab>`; `#/users` and `#/audit` are legacy aliases). Cloud secrets are write-only through the API (`publicConfig` strips them); blank secret fields on save mean "keep".
- Restore is two-step in `app.js` (`/api/admin/restore/inspect` stages + validates via `restore.js`, migrating old schemas on the staged copy; `/apply` writes a safety backup, then `db.swapFile()` replaces the file under the live handle and clears `sessions`). `db.js` exports a `Database` wrapper (not a bare `DatabaseSync`) precisely so the file can be swapped; keep using only `prepare`/`exec`/`close` on it. Raw DB uploads go through `RAW_PATHS` in `server.js`.
- Versioning: SemVer, source of truth is `server/package.json` (mirrored in `web/package.json` + lockfile); releases are git tags `vX.Y.Z`. Cut them with `node scripts/release.mjs <bump|X.Y.Z>` (bumps, rolls `CHANGELOG.md` `[Unreleased]`, commits, tags; never pushes). CI (`scripts/ci-version.mjs check`) rejects a tag that disagrees with the package versions or lacks a CHANGELOG section. The image gets `APP_VERSION`/`APP_COMMIT` build args, surfaced via `/api/me` and `/api/admin/system`. Docker `latest` = newest stable release, `edge` = main. Keep `CHANGELOG.md` `[Unreleased]` updated with user-visible changes.
- First run: `/api/me` returns `setup_required` while there are no users and the UI (`Auth.jsx`) shows the "create administrator" screen; it still goes through `/api/auth/register`, where `auth.register` makes the very first account global Admin and everyone after gets no role assignment (= None). `/api/me` gives admins `pending_users` (users with zero role rows) for the sidebar badge.
- Sign in with Google: `google-login.js` (OIDC code flow + PKCE, reuses helpers from `gdrive.js`), config in `settings.google_login` (separate OAuth client from the Drive one), identities in `user_identities(provider, subject)`; `auth.loginWithIdentity` creates role-less users and honours `registration_open`. Callbacks (`/api/auth/google/callback`, `/api/admin/backups/gdrive/callback`) answer with `{ redirect }`, which `server.js` turns into a 302.
- API docs: `src/openapi.js` holds a `DOCS` table (tag, summary, access, body/query) and builds the OpenAPI spec from the live `routes` table; `/api/openapi.json` + `/api/docs` are public. `test/openapi.test.js` fails when a route has no `DOCS` entry (or vice versa), so add the entry whenever you add a route.
- Backup encryption: `backup-crypto.js` (AES-256-GCM, `SIPAMENC1` header, scrypt key); `settings.backup_config.encrypt` (passphrase stored in DB so scheduled backups can run); files are `*.db.enc`; restore decrypts in `/restore/inspect` (typed passphrase → `X-Backup-Passphrase` header → stored one).
- UniFi: `unifi.js` is a read-only client for Site Manager (`api.ui.com`, header `X-API-Key`; console data via `/v1/connector/consoles/{id}/proxy/network/integration/v1/...`) with tolerant parsers (`toNetwork` searches for `hostIpAddress`/`prefixLength`/`ipAddressRange` because the public spec does not pin the nesting). Sync lives in `app.js` (`unifiFetchConsole` does the awaits, `unifiApply` writes in one synchronous transaction; `observeMac` is shared with scans). Config in `settings.unifi`, last run in `settings.unifi_last`. Tests use a fake `api.ui.com`; it has not been run against real hardware, so adjust parsers to real payloads first if anything is off.
- Aliases: `entries.alias` (user-visible) and `entries.unifi_name` (alias as last seen in UniFi = merge base). `unifiApply` does a three-way merge: only UniFi changed → take it, only IPAM changed → keep, both → IPAM wins (counted as `aliases.conflicts`). IPAM → UniFi write-back (`unifiPushSite`/`unifiPush`, `POST /api/admin/unifi/push`) goes through the classic API (`/proxy/network/api/s/{site}/rest/user`, by MAC) because the Integration API cannot rename clients; imported sites remember their console in `sites.unifi_host/unifi_site/unifi_site_name`. Automatic push (`push_aliases`) can only be enabled after one successful manual write (`write_verified`); `pushAliasSoon` fires after an alias edit. The classic-API paths are written from third-party docs and are not yet verified on real hardware — `/api/admin/unifi/diagnose` is the read-only probe.
- i18n: Polish is the source language and the Polish text is the translation key. `web/src/i18n.js` exposes `t(key, vars)` (exact key, then placeholder patterns such as `Usunąć {name}?`, so already-interpolated strings and server messages translate too), `useLang`/`setLang` (stored in `localStorage.lang`, default from `navigator.language`). Dictionaries live in `web/src/i18n/en.js` / `de.js`; `Field`, `Modal`, `Toasts` and the label tables in `ui.jsx` translate their string props themselves. The server stays Polish; `api.js` translates error messages (`err.raw` keeps the original). Every new UI string needs an en + de entry (`server/test/i18n.test.js` checks coverage of literal `t('…')` keys and placeholder parity). In `App.jsx` the function is imported as `tx` because tenants are called `t` there. OpenAPI descriptions and the README are English.
- Excel export: `server/src/xlsx.js` is a dependency-free SpreadsheetML writer (inline strings, deflated ZIP via `node:zlib`, `zlib.crc32`); `app.js` builds the sheets in `xlSheet` (headers/labels per `?lang=`). The entry "kind" (static / dynamic / DHCP reservation) is derived from the network's DHCP range everywhere (`netStats`, issues, xlsx, UI `statusChoices`/`inPool`). `issuesOf(net)` feeds `/networks/:id/issues`, `/api/issues` and `stats.issues`. UI: `ask()`/`<ConfirmHost/>` in `ui.jsx` replace `window.confirm`; `notify(text, kind, { label, fn })` adds an action (undo) to a toast.
- Planning: `pools` (per tenant, each bound to a `site_id`; `db.js` assigns legacy pools to a site on open). A network is VLAN + subnet: `networks.vlan` is required by `netInput` and unique per site (`vlanFree`); there is no VLAN registry any more (legacy `vlans` table is just left unused). Imports (UniFi/Azure) may still store a NULL vlan, which `issuesOf` flags. `GET /api/tenants/:id/plan` computes allocations/free blocks/conflicts on the fly using `freeBlocks`/`findFree`/`mergeRanges` in `ip.js`; `POST /api/pools/:id/allocate` creates a network in the pool's site (gateway defaults to `first`; `netInput` also accepts `first`/`last`). Access is tenant-level (`needTenant`). UI is `web/src/Planner.jsx` (`#/plan/<tenantId>`). The gateway is never a `discovered` host: `scan` stores `networks.gateway_mac/gateway_seen` instead, and network/broadcast addresses are rejected by `entryInput` and rendered as virtual rows (`sysRow`) in `Network.jsx`.
- Azure: `azure.js` is a read-only ARM client (SPN client-credentials token from `login.microsoftonline.com`, `management.azure.com` lists with `nextLink` followed only on that host; `fetch` injectable) with tolerant parsers `toSubnets`/`toInterfaces`/`toFrontends`. Config in `settings.azure` (secret write-only via `azurePublic`), last run in `settings.azure_last`. `azureSync` mirrors `unifiSync`: fetch per subscription (awaits), then `azureApply` in one synchronous transaction (rolled back for `dry_run`). Location = subscription (`sites.azure_sub` keeps the link across renames), network = VNet subnet (`vnet / subnet`, gateway `.1`), entries = NIC IP configs + internal LB frontends; only blanks are filled on re-runs. Not yet run against a real tenant — `/api/admin/azure/diagnose` is the read-only probe.
- Network page extras: `GET /api/networks/:id/changes?days=` (appeared = `discovered.first_seen`, silent = `entries.last_seen` older than the window but only when something was seen inside it, added/removed from `entry_history`); `issuesOf` also flags a discovered host whose MAC belongs to an entry at another IP. `IpMap` in `Network.jsx` is a patch panel (rows of 16, 8 on phones); map cells and table rows share `data-n` (numeric address) and are cross-highlighted by `light()`. Fonts (IBM Plex) are bundled through `@fontsource` imports in `main.jsx`, never a CDN. Light/dark colour tokens live at the top of `styles.css`; keep text pairs at WCAG AA (4.5:1) when changing them.

- Notifications: `notify.js` (`compose` batches, `send` posts ntfy text with an RFC 2047 `Title` or a JSON webhook carrying both `text` and `content`; `fetch` injectable). In `app.js`, `queueNotify`/`flushNotify` collect findings for `notifyDelayMs` (default 5 s) and send one message; hooks are `noteNewHost` (scan and UniFi, must run *before* the `discovered` insert so only first sightings count) and `observeMac`. Config in `settings.notify` (URL write-only via `notifyPublic`), last delivery in `settings.notify_last`; UI is the `Notifications` card in `Admin.jsx`.
- QR labels: `web/src/Labels.jsx` (client-side only; `qrcode-generator` is the one runtime dependency of the web app besides Preact and the fonts). A label's QR is `<base>/#/n/<networkId>?ip=<ip>`; `Network.jsx` reads `?ip=` from the hash and flashes that row (`flashed` guards against repeating). Printing is `window.print()` with `@media print` rules that hide everything except `.page > .overlay .label-sheet`; `.modal` must get `width: 100%` and `container-type: normal` there (inline-size containment otherwise collapses it to 0). A `<style>` inside the modal sets `@page` margin (10 mm plain paper / 0 sticker sheets).
